## 评测对象

- **产品**：Travel Monkey（仓库目录 `travel-monkey-agent`）——行程页生产工作台：模型填 trip JSON，本机调研、交通、配图、主题、校验。
- **阶段标签**：技术 MVP / 内部 Demo；尚未进入人格化产品期。
- **总判断**：骨架强，业务脑弱。路径、景点、三餐、住宿是四件独立业务；住宿不是餐饮附属。

## 怎么打分

先定性，再给分。同一轮必须写清：已立住、缺口、实现粒度、是否合理、完善程度。

| 分数带 | 含义 |
|---|---|
| 0–3 | 题目要求基本没落地，或和题目不对齐 |
| 4–5 | 能演示，靠模型临场；没有规则兜底 |
| 6–7 | Demo 可用；反复用会翻车或缺人格 |
| 8–9 | 可给真实用户反复用、少翻车 |
| 10 | 该维度已达产品目标，不必再作为主缺口 |

**工程标准化**取专业五维算术均值（四舍五入到 0.1）。  
**三类用户适配**取三个人格分算术均值。  
**四项业务完成度**取路径 / 景点 / 三餐 / 住宿算术均值。

交通分默认按「已填高德 Key」估；无 Key 时路径约 3 分。住宿分按契约与版面估，不按适老或可订估。

复评时：对照下文锚点改分，更新日期与依据；不要只改画布不改本文快照。

### 复评纪律（加分与改分规则，2026-09-30 起执行）

1. **bugfix 不改分**：同档内的修对、补渲染、加固、条目小幅增加，只更新 CAPABILITY，不碰快照。
2. **跨档才改分**：每次改分必须写清勾上了哪条高分锚点（例："适老结构化字段已渲染"），不写"优化了住宿"这类空话。
3. **一次只推一维**：按杠杆排序逐维做——住宿 → 专业性（线路库） → 三餐 → 体验 → 稳定性 → 路径；一轮复评只验收申报的那一维。
4. **证据链**：改分需附可运行验证（`node` 单测输出、golden 回归通过、模具渲染命中），无验证不改分。
5. **降级同步降分**：无 Key 场景的分数另行标注，不与有 Key 分数混用。

## 1. 专业维度

对照「正规 Agent + 可上线旅行产品」，不是对照竞品 App。

### 1.1 标准化

页面与流程是否有契约，模型是否被管住。

| 锚点 | 典型证据 |
|---|---|
| 高 | 每天固定 6 格；模型禁写 HTML/CSS；PLAN / FILL / TALK / EDIT 分模式；`validateAll` 失败回退陶土模具 |
| 低 | 意图只靠正则；无用户画像；无线路知识库；无质检清单；模具能画的字段 FILL 不强制 |

可上线门槛：8.0。

### 1.2 旅行专业性

内容是否像资深规划，而不是填表散文。

| 锚点 | 典型证据 |
|---|---|
| 高 | 经典线路库；代表性 / 性价比可校验；老人节奏与医疗；徒步难度与补给；住宿有适老 / 连住 / 集合点判断 |
| 低 | 质量绑在模型临场；价格与店名写「参考」却无核验；无「必看 / 可砍」 |

可上线门槛：7.5。诚实（`dataSources`、不代订）加分，但不等于专业。

### 1.3 实用性

真实用户能否靠它做完「规划 → 出页 → 小改 → 带走」。

| 锚点 | 典型证据 |
|---|---|
| 高 | 先大纲后出页；改一天不重规划；H5 / 长图 / 分享可用；无 Key 时仍诚实降级 |
| 低 | 冷门点配图常错；改行程答非所问；密钥和工作台挡住目标用户 |

可上线门槛：8.0。

### 1.4 稳定性

分两层：页面稳、内容稳。只页面不崩不能给高分。

| 锚点 | 典型证据 |
|---|---|
| 高 | 模具兜底；编辑打补丁；调研不每轮重跑；密钥拒绝页面 URL；配图宁空不配错 |
| 低 | 配图误匹配；talk / edit 误判；导出超长画布翻车；交通段数硬顶且模式单一 |

可上线门槛：8.0。

### 1.5 用户体验（对话体验）

对话是否像顾问，界面是否目标用户读得懂。

| 锚点 | 典型证据 |
|---|---|
| 高 | 提问只回答、改行程只打补丁并点名格子；老人大字少术语；改完读新安排，不报主题名 |
| 低 | 开发者工作台；套话循环；主题名当「已改好」；待确认自动提交 |

可上线门槛：7.5。与「合理性」分开：体验看交互，合理性看产品决策。

### 1.6 合理性（横切）

方案对不对，不是分高不高。工程合理 ≠ 产品合理。

必须同时回答：

1. **工程**：6 格模具、模型填表、本机工具——是否省 token、可校验、可分享。
2. **产品**：同一套观光日是否服务得了三类人；住宿是否被当成餐饮附属；能力写在渲染层还是规划契约。
3. **业务**：四件业务是否各有字段，还是挤进 6 格凑数。

判定句式：「作为 Demo 合理 / 作为带队依据不合理」。合理性出问题，优先改契约，不先加皮。

### 1.7 完善程度（横切）

某件事做到哪一档，用固定动词，避免「差不多」。

| 档 | 动词 | 含义 |
|---|---|---|
| 未完成 | 能凑 | 题目要求没写成契约，靠格子或种子手工补 |
| 半完成 | 能标 / 能写 / 能列 | 有结构或能出字，不能当依据 |
| 可用 | 能用 | 有 Key、名点、主路径时反复用少翻车 |
| 完成 | 住得对 / 看得懂 / 算得清 | 对照人格与四项业务，可当规划依据 |

完善程度写在每条业务上，不单独打 0–10（0–10 用业务完成度）。

## 2. 目标用户

三个用户要的不是同一张行程页。各打一适配分，再取均值。

| 人格 | 要什么 | 产品目标 | 低分信号 |
|---|---|---|---|
| 退休旅居 | 慢、暖、细、少折腾；半天一点；适老入住；大字少术语 | 8.5 | 一天三景偏满；入住只有店名；语气是填表助手 |
| 资深导游 | 经典、代表、性价比；必看/可砍；停车集合；团操 | 8.0 | 像学员作业；酒店区像推荐文，没有团操字段 |
| 专业驴友 | 值不值得、专业不专业；难度补给；走完取车再住 | 8.0 | 观光日够用、探秘不够格；种子后勤链不会自动复用 |

合理性要求：共用 6 格骨架，再加「旅居 / 带队 / 探秘」三套规划与入住规则，而不是再加皮肤。

## 3. 四项业务问题

住宿是独立业务，不是餐饮附属。结构完整度可以高于三餐，专业判断仍可给低分。

| 业务 | 问什么 | 高分证据 | 低分证据 |
|---|---|---|---|
| 路径 | 线路、交通、距离、时间是否算得清 | 全天路径引擎；按人格选步行/公交/包车/高铁；超负荷警告 | 只有邻点补丁；最多 N 段；跨城未建模 |
| 景点 | 沿途经典点是否看得懂、建议是否站得住 | 图文准确；必看/可跳；简介可核验 | 冷门点空或错；简介看模型临场 |
| 三餐 | 每日早、中、晚是否有特色与禁忌 | `dining[]` 或早/午/晚强制；软硬、就近、禁忌 | 只强制第 6 格晚餐 |
| 住宿 | 是否住得对（片区、档位、连住、适老） | `hotelAreas` 与当日 `stay` 对齐；电梯/一层/坐便；连住；集合点/停车 | 只有店名+片区理由；店名常编；不能代订却装得像可订 |

### 补丁健壮性专轮备注（2026-09-30 深夜，不改分）
- 前一轮修的是"话被送错车道"，这一轮是"车到了但货卸不下来"：改表只认 `{day,slot,set:{name}}` 一种形状。模型把值平铺成 `{day,slot,name}`（极常见）→ 判「没有 set」整条丢弃；餐、规划条同病。
- 更要命的一类：模型只回一句「我已经把第二天的人头山换成翠华山了」而不给补丁。本机照实什么都不改，还把模型那句假话原样转给用户——"模型输出了结果、页面没更新"的完整成因。
- 三层修：①平铺补丁照收（`liftSet`）；②模型口头声称/反问/回纯文本时，按用户原话本机兜底改（`inferEditFrom`）；③一个补丁都没落地时不转述「已改好」（`stripEditClaim`），只说「这次没有改到页面上」并给可用句式。顺带修掉 `把day2的人头山换成X` 里定位词带「的」导致找不到格子的老问题。
- 按纪律：bugfix 不加分。但"改表对模型输出格式的容错"是 EDIT 链能不能用的底线，golden 41→49 全覆盖。

### 意图路由专轮备注（2026-09-30 晚，不改分）
- 根因不在渲染而在**路由**：`wantsPhotos` 没收「图片/照片」两个最常用的词，于是「优化day1、day2的景点图片」被 `优化…点` 误判成改表 → 交给模型 → EDIT 契约明写「问图不要改表」→ 模型回空补丁 → 页面一动不动；「一方小院图片不对，请更换」连改表都没进，直接掉进纯聊天。用户看到"模型答了、页面没变"，两边都没撒谎。

### 附件与看图专轮备注（2026-10-01，不改分）
- 新增能力两件：①输入框收图片/文本附件（粘贴、拖拽、选文件）；②图片真送给模型看（`look` 模式，本机图内联 base64，OpenAI／Anthropic 两种报文都验过）。
- 关键设计是**分流**，不是"把图一律丢给模型"：「D2第2格用这张图」走本机直贴，不花钱不走网络；「这是哪／图里写的什么」才烧 token。说不清时默认贴图（本机再问一句，成本更低）；页面还没出来时图没处贴，才默认送模型。
- 诚实度延续前几轮：`LOOK_SYSTEM` 强制分清「看得见的」（招牌、路牌、票面）和「推测的」并写明把握，认不出就说认不出，禁止硬凑景点名；看图这轮明说不动页面，不许再出现"说改了其实没改"。选了不认图的型号直接拦下并点名替代，不白烧一轮。
- 顺带还债：`src/lib/target.ts` 的 `Day` 类型一直是 `NonNullable<Trip['days']>[number]`，而 `Trip` 带索引签名 → 推成 `{}`，14 条类型报错长期被漏看（之前几轮的"tsc 干净"只扫了改动文件，没覆盖这个文件，是我核查范围的疏漏）。现全项目 `tsc --noEmit` 0 报错。
- 按纪律：新增输入通道**不对应任何一条已列锚点**（质检清单／走线校准／跨会话记忆／当日陪伴），按"跨档才改分、一次只推一维"不动快照。golden 49→67。
