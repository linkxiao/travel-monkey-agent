# Travel Monkey 上下文与记忆评测标准

本文是「上下文、记忆、多轮会话」这一维的**源文档**：怎么打分、当前快照、待办和验收口径。总尺子仍是 [EVAL.md](./EVAL.md)，本文是它的专项展开；改分纪律沿用 EVAL「复评纪律」（跨档才改分、证据链、一次只推一维）。

依据是代码，不是体验印象。每次复评对照现码：`src/App.tsx`（会话状态与编排）、`src/lib/trip.ts`（`digestTrip`）、`src/lib/memory.ts`（约束板）、`src/lib/session.ts`（会话存储）、`src/lib/context.ts`（每轮消息怎么拼）、`server/skill-prompt.mjs`（各模式提示词）。

---

## 1. 评测对象与边界

- **上下文**：每一轮实际发给模型的是什么、多长、从哪来。
- **短期记忆**：同一趟行程里，前面说过的话和定过的事，后面还在不在。
- **长期记忆**：跨行程、跨天，记不记得「这个人」。
- **多轮会话管理**：阶段切换（规划 → 待确认 → 出页 → 改稿）、刷新恢复、多趟行程切换。

不在本文范围：意图识别准不准（见 EVAL 1.4 稳定性、CAPABILITY 3.2）、线路知识召回（那是检索增强，不是记忆）。

## 2. 四个子维度与锚点

分数带同 EVAL：0–3 没落地；4–5 能演示；6–7 一次会话内可用、换场景会丢；8–9 真实用户反复用少翻车；10 不再是主缺口。

### 2.1 上下文管理

| 锚点 | 典型证据 |
|---|---|
| 高 | 以结构化事实（`trip` JSON）为唯一来源，每轮压成短摘要；可按天裁剪；按模式挂不同提示词；能本机落表就不打模型；上下文长度不随轮数线性增长 |
| 低 | 每轮塞全量历史或整页 HTML；旧版本点名混进历史导致改错；摘要里缺硬约束 |

可上线门槛：8.0。

### 2.2 短期记忆（本趟行程内）

| 锚点 | 典型证据 |
|---|---|
| 高 | 用户说过的硬约束（人数、忌口、身体、预算、出发地、日期）结构化记下，**每一轮**都带上；规划阶段不因大纲漏写而丢约束；窗口外的旧对话有滚动摘要 |
| 低 | 只靠「最近几条原文」；约束要模型自己记得写进大纲；聊到第五六轮前面的偏好就滑出窗口 |

可上线门槛：8.0。

### 2.3 长期记忆（跨行程）

| 锚点 | 典型证据 |
|---|---|
| 高 | 用户画像（人格、忌口、住宿档位、常住片区）在新行程开始时注入；**用户确认后才写入**；界面可看可删；上云后按账号隔离 |
| 低 | 只记设置和页面版本；或者偷偷记、不能删；或者把一次性的事（这趟带孙子）当成长期偏好 |

可上线门槛：7.0。宁可少记，不可错记。

### 2.4 多轮会话管理

| 锚点 | 典型证据 |
|---|---|
| 高 | 会话有 ID；阶段、对话、大纲、调研、行程、版本、约束一起持久化；刷新即恢复到原阶段；可新建、切换、删除多趟行程 |
| 低 | 状态只在页面内存；刷新失忆；新行程只能靠刷新；版本回退和对话脱节 |

可上线门槛：8.0。

## 3. 快照 · 2026-10-02（首评）

依据：`recentChat` 只带最近 2～4 条；`runPlan` 只带调研摘要 + 当前大纲 + 本句；`bubbles` / `trip` / `planDraft` / `researchRef` 只在 React 状态与 ref；`localStorage` 只持久化设置与 `ct.versions`（最近 5 版）；无会话 ID；全项目无 LangChain / LangGraph / 原生工具调用。

| 子维度 | 分 | 一句话 |
|---|---|---|
| 上下文管理 | 7.5 | `digestTrip` 领域摘要 + 分模式 + 调研只跑一次，做得克制；缺「硬约束」这一块 |
| 短期记忆 | 5.0 | 出页后只有 2～4 条窗口，无摘要；规划阶段前几轮的话不带，约束靠大纲碰运气 |
| 长期记忆 | 2.0 | 只记设置与 5 个页面版本，不记人 |
| 多轮会话管理 | 4.0 | 阶段状态机清楚，但刷新失忆、无会话 ID、不能切换行程 |
| **均值** | **4.6** | 一次会话内可用；跨刷新、跨行程不可用 |

### 3.1 已立住

- `trip` JSON 为唯一事实源，`digestTrip` 每轮压成短摘要，可按天裁（`opts.day`）。
- 分模式提示词：PLAN / FILL / TALK / EDIT / LOOK，互不串台。
- 调研只做一次，改天不重跑；能本机落表（同步、第 N 格、新增点）就不打模型。
- 抱怨或「继续优化」时回放最近几句用户原话（`requestPack`）。
- 版本回退：内存近 10 版，`localStorage` 近 5 版。

### 3.2 缺口（按伤体验程度）

1. **规划阶段丢约束**：`runPlan` 只发「调研 + 当前大纲 + 本句」。第一轮说「我妈膝盖不好、不吃辣」，第二轮说「改成 5 天」，若首版大纲没写进这两条，第二轮模型就看不到了。只有人格单独记了（`planningPersona`）。
2. **出页后窗口固定、无摘要**：`recentChat` 默认 4 条、改稿 2 条，窗口外的偏好直接丢，除非已落进行程表。
3. **刷新失忆**：对话、大纲、调研、当前行程都不持久化；页面能靠版本回退找回，对话找不回。
4. **单会话**：没有会话 ID，没有「新建 / 历史行程」，新行程只能刷新。
5. **不记人**：跨行程不记人格、忌口、档位。
6. **存储选型风险**：`localStorage` 约 5MB，已存 5 份整页 HTML，再往里堆会撞配额。

## 3b. 快照 · 2026-10-02（M1 + M2 + M3 落地后）

依据：
- `src/lib/session.ts`：IndexedDB `travel-monkey`，`sessions` 表存全量、`meta` 表只存列表项；当前会话 ID 记在 `localStorage` 的 `ct.session`；无痕模式打不开库时退化为只在内存。
- `src/App.tsx`：启动时按 `ct.session` 恢复对话（丢掉生成中的半截气泡）、大纲、人格、调研、当前行程与页面、约束、版本；空闲 400ms 自动存，切换 / 新建前先立刻存一次；版本改存进会话（近 10 版），旧 `ct.versions` 首次存盘后删除；左栏会话条「历史下拉 + 新建行程 + 删除」。
- `src/lib/memory.ts`：约束板九类（同行、身体、忌口、日期、天数、出发地、交通、住宿、预算），正则本机抽取，问句不抽，「第 N 天」不当天数；天数 / 日期 / 预算 / 出发地 / 交通只留最新，人数换新时「带老人」之类并存；封顶 12 条。
- 注入：`runPlan` / `runFill` 在调研后插一对约束消息；`recentChat` 把约束块放在行程摘要前（覆盖 TALK / EDIT / 有行程的 LOOK）；无行程的 LOOK 也带。`EDIT_SYSTEM` 加可选 `facts`，`extractEnvelope` 透出，`runEdit` 合并。
- 证据：golden 96/96（新增 23 条：抽取、合并、删除、模型 facts、会话判空与标题）；浏览器实测（mock 模型）三轮后第三次请求含「膝盖不好 / 不吃辣 / 6人 / 4天3晚」，刷新后 6 条气泡与 4 条约束原样恢复，新建后清空、切回后复原，删一条约束刷新后仍是删掉的。

| 子维度 | 分 | 变化 |
|---|---|---|
| 上下文管理 | 8.0 | +0.5：每轮带结构化硬约束，与摘要冲突时以约束为准 |
| 短期记忆 | 7.0 | +2.0：规划阶段前几轮的硬约束不再丢；软偏好（M4）和窗口外摘要（M5）仍缺 |
| 长期记忆 | 2.0 | 不变：跨行程不记人（M6） |
| 多轮会话管理 | 8.0 | +4.0：刷新不失忆、多会话可切可删；服务端会话（M7）未做 |
| **均值** | **6.3** | 单机多会话可用；跨设备与长期画像不可用 |

剩余缺口：3.2-2 窗口外的软偏好、3.2-5 不记人；本机正则只认常见说法（例如「我妈腿脚不便」能抽，「我妈不太能走」抽不到），靠模型 `facts` 补，但目前只有 EDIT 回 `facts`，PLAN 阶段没有模型补抽。

## 4. 目标架构：四层记忆

| 层 | 存什么 | 存哪里 | 怎么进上下文 |
|---|---|---|---|
| 工作记忆 | `trip` JSON | 会话内 | `digestTrip`（已有） |
| 会话约束 | 本趟硬约束：人数、同行、忌口、身体、预算、出发地、日期、交通、住宿偏好 | 会话内，结构化 `constraints[]` | 每轮固定放在最前，约 100 字 |
| 会话历史 | 对话、大纲、调研、版本、阶段 | IndexedDB；上云后放服务端 | 最近几条原文 + 更早部分的滚动摘要 |
| 长期画像 | 人格、忌口、住宿档位、常住片区 | 本机；有账号后放数据库 | 新行程开始时注入；用户确认才写 |

原则：

1. **事实结构化，不靠原文**。约束写成「类别 + 值 + 来源」，不是把用户原话塞进去。
2. **每轮都带，但很短**。约束块封顶 16 条、按类别一行。
3. **用户能看、能删**。约束和画像都要在界面上露出来，删了就不再进上下文。
4. **本机抽取兜底，模型抽取补充**。正则先抽常见项（零成本、可测）；模型在已有 JSON 回复里顺手回 `facts`，不另起一轮。
5. **宁少勿错**。抽不准的不记；一次性的事不进长期画像。

## 5. 框架选型结论

| 框架 | 结论 | 理由 |
|---|---|---|
| LangChain | 不用 | 它的对话记忆解决「把历史拼进提示词」，本项目已用领域摘要做得更好；核心价值在本机规则、校验、落表，框架帮不上，反而加依赖。服务端是零框架 `.mjs`，部署简单是优点 |
| LangGraph | 现在不用，满足条件再上 | 流程本身就是状态图（调研 → 大纲 → 待确认 → 填表 → 校验 → 修表 → 改稿循环），检查点 / 中断 / 线程正好对应会话持久化 / 等用户确认 / 多会话。但当前编排在浏览器，模型不调工具，硬套只是换写法 |
| 向量库 | 现在不用 | 画像是十几个结构化字段；向量检索留给线路库召回 |

**上 LangGraph.js 的触发条件**（满足任意两条）：

- 部署成多用户服务，会话状态必须放服务端且多实例共享；
- 让模型自己决定调用高德、搜索、天气等工具，形成「思考 → 调工具 → 再思考」循环；
- 有长时后台任务（出发当日陪伴、定时提醒），需要中断续跑、可回放。
